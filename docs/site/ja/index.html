コンピューターが何をしているかを、Windows でも Mac でも 1 つのウィンドウで

Hexnest は、マシン本体と個々のプログラムがプロセッサ時間・メモリ・帯域をどれだけ使っているか、ログイン時に何が勝手に起動するか、ディスク容量が実際どこへ消えたのかをリアルタイムに示します。推定ではなく実測です。Windows では本格的なドライバー更新ツールにもなり、すべてのデバイスを調べ、不足・旧版のドライバーを Windows Update カタログや USB メモリ上のフォルダーから導入し、ドライバーのインストールに必要な再起動をまたいで作業を続け、インターネットがまったくなくても以前のドライバーを元に戻せます。

Windows 10 1607 以降と Windows 11 · macOS 12 Monterey 以降 · 64 ビット、Apple シリコンと Intel · MIT ライセンス

最近追加 1.5.0

以下はすべて、配布されているアプリケーションに入っています。機能一覧のふりをしたロードマップはありません。

  • スタートアッププログラム

    Windows がログイン時に実行する自動起動項目のすべて — レジストリの Run キーと 2 つのスタートアップフォルダー — を、1 つずつスイッチで。無効化はタスクマネージャーが書き込むのと同じ設定を書くので、両者は常に一致し、元のコマンドラインが消えることはありません。存在しないファイルを指す項目には印が付きます。Windows はそれをログインのたびに試し、黙って失敗しています。

  • クリーンアップ

    一時ファイル、サムネイルとアイコンのキャッシュ、7 種類のブラウザー、Windows Update のダウンロードキャッシュ、クラッシュダンプ、シェーダーキャッシュ、保守ログ、そしてごみ箱。サイズはすべて推定ではなく実測なので、チェックボックスの横の数字は本当に戻ってくる容量です。しかも、こちらで勝手にチェックは付けません。

  • あなたのファイルはあなたのもの

    古いダウンロードや、アンインストール済みソフトが残したフォルダーが一括選択されることはありません。サイズと経過期間を添えて 1 件ずつ並び、1 件ずつチェックし、削除ではなくごみ箱へ送られます。残骸の判定はあくまで推測であり、ページにもそう書いてあります。

  • システムモニタ

    論理コアごとのバーで示すプロセッサ負荷、キャッシュ済み・コミット済みバイトまで分解したメモリ、ファームウェアが公開しているすべての温度センサー、読み書きの実測スループット付きのストレージ容量、そしてバッテリー状態。加えて、実行中の全プログラムとその負荷の一覧。

  • ネットワークモニタ

    マシン全体のダウンロードとアップロードをリアルタイムに、今回のセッションと Windows 起動以降の合計、アドレスとリンク速度付きの全アダプター、そしてどのプログラムが接続をどれだけの速度で使い、いくつの接続を開いているかを示すアプリ別の表。

  • 自動更新

    Hexnest は 1 日 1 回だけ GitHub に新しいリリースの有無を尋ね、メニューで知らせます。ダウンロードとインストールは既定でオフのままで、オンにしても検証済みのファイルが差し替わるのはアプリの終了時だけ — ドライバーのキューの途中では決してありません。

  • 10 の言語

    英語、トルコ語、ロシア語、簡体字中国語、ヒンディー語、ポルトガル語、日本語、ドイツ語、フランス語、韓国語。すべてが単一の実行ファイルに入っており、再起動なしで切り替えられます。 Hexnest.exe の隣に JSON ファイルを置けば、ビルドし直さずに翻訳を追加・修正することも従来どおり可能です。

  • バッテリーと電源

    Windows に対応するページのない macOS 専用のページです。問いがノート型のものだからです。充放電回数、macOS 自身が報告する最大容量、状態、バッテリー自身の温度 — その下には、Mac を起こしたままにしている各プロセスと、取得したアサーション、保持時間。タイマーではなくページを開いたときに読み取ります。毎秒サンプリングするページは、バッテリーの話をするためにバッテリーを消費してしまうからです。

見た目はこんな感じ

配布中のアプリケーションから撮った実際のスクリーンショットで、Windows 11 のノート PC で取得したものです。 Hexnest.exe --captureでビルド自体から再生成するため、内容が古くなることはありません。

これを作った理由となった問題

Windows を入れ直したばかり。デバイスマネージャーは黄色い感嘆符だらけ、解像度はおかしく、音は出ず、そして何より — インターネットがない。ネットワークアダプターにもドライバーがないからです。ドライバーを落とすにはインターネットが要り、インターネットに出るにはドライバーが要る。

Hexnest はこの堂々巡りを 1 つのウィンドウで断ち切ります。ハードウェアを列挙し、実際に取得できるドライバーと突き合わせ、インストールする。ネットワークがまったくない場合は、持ち込んだフォルダーからインストールします。

Hexnest にできること

以下はすべて配布中のアプリケーションに入っています。機能一覧のふりをしたロードマップはありません。

  • すべてのデバイスを調べる

    存在する PnP デバイスを WMI ではなく SetupAPI と CfgMgr32 で列挙します。だから 5 分前にフォーマットしたばかりのマシンでも、WMI リポジトリが壊れたマシンでも動きます。

  • 不足しているドライバーを見つける

    構成マネージャーの問題コードをリアルタイムに読み取ります。コード 28、1、19 は「ドライバーなし」、22 は無効化されたデバイス、14 は再起動待ちです。フィルターで、問題のあるデバイス、ドライバーのないデバイス、汎用ドライバーで動いているデバイスを切り替えて見られます。

  • Windows Update のドライバーカタログを使う

    もともと Windows に入っている Windows Update エージェントの COM API 経由で Microsoft Update と通信します。追加のサービスも、間に入るサードパーティのドライバーミラーもありません。

  • USB メモリからオフラインでインストール

    任意のフォルダー — USB メモリ、ネットワーク共有、Hexnest のバックアップ、自分で展開したメーカー配布物 — にある INF パッケージを解析し、あなたのハードウェア ID と突き合わせます。

  • 並列でダウンロードし、1 件ずつインストール

    既定で 3 並列のダウンロード、1 から 8 まで設定可能。インストールを直列にしているのは意図的です。Windows Update は 2 件目の同時インストールに WU_E_OPERATIONINPROGRESS を返しますし、PnP サブシステムはどのみち直列化します。

  • 再起動を乗り越える

    キューの状態は変更のたびに session.json へ書き出され、ログイン時に起動されるタスクスケジューラのタスクが --resume付きで Hexnest を呼び戻します。だから 3 回の再起動を要する 10 件のキューも、自力で最後まで終わります。

  • 何かを変える前にバックアップする

    セッション最初のインストール前にドライバー種別のシステム復元ポイントを作り、置き換える直前に各ドライバーパッケージを書き出して、そのパスを履歴に記録します。

  • ドライバー一式のバックアップと復元

    サードパーティ製ドライバーパッケージをすべて pnputil /export-driver でフォルダーか ZIP に書き出し、 pnputil /add-driver /subdirs /installで戻します。Microsoft 同梱のドライバーは意図的に除外します — あれは Windows が自分で入れ直すからです。

  • ハードウェアレポートを書き出す

    すべてのデバイスとハードウェア ID をプレーンテキストで保存。USB メモリで動く別のコンピューターへ持って行き、ほかに手立てがないときに手作業でドライバーを調べられます。

  • 正直な履歴を残す

    すべてのドライバー操作を 1 行 1 JSON オブジェクトとして恒久的に記録し、結果で絞り込み、ワンクリックで CSV に書き出せます。加えて、バージョンと OS のヘッダー付きでコピーできるリアルタイムの診断ログ。

  • 自分自身の更新を検証する

    内蔵の更新機能は、ダウンロードしたものをリリースの checksums.txtにある SHA-256 と照合し、チェックサムが無い場合や一致しない場合は何もインストールしません。バックグラウンドで黙って更新することは決してありません。

  • マシンの状態を見せる

    論理コアごとのプロセッサ負荷、キャッシュ済み・コミット済みバイトまで見えるメモリ、ファームウェアが実際に公開している温度センサー、実測の読み書きスループット付きのストレージ容量、バッテリー状態をリアルタイム表示。ページを開くまで何も計測せず、離れた瞬間に止まります。

  • 各プログラムの負荷を見せる

    実行中の全プロセスのプロセッサ占有率、ワーキングセット、プライベートバイト、ディスクスループット、スレッド数を、タスクマネージャーと同じ方法で計測。並べ替え、検索、一時停止ができます。

  • 帯域の行き先を見せる

    マシン全体のダウンロードとアップロードはアダプター自身のカウンターから、アプリ別の通信量は Windows の TCP 接続統計から取得します。カーネルドライバーも、パケットキャプチャも、サードパーティのサービスもありません。

  • 自分を最新に保つ

    1 日 1 回の GitHub Releases API へのリクエストが、新しいバージョンの有無を知らせます。自動ダウンロードとインストールはオプトインで、SHA-256 で検証され、適用されるのは Hexnest の終了時だけです。

  • Windows と一緒に起動するものを管理する

    レジストリの Run キーと 2 つのスタートアップフォルダーにある自動起動項目のすべてを、1 つずつスイッチで。無効化はタスクマネージャーが書くのと同じ StartupApproved の値を書くだけなので、何も削除されず、2 つのツールは常に一致します。Hexnest をアンインストールしても、スタートアップ項目が半分消えているということは起こりません。

  • 容量を食っているものを実測する

    キャッシュ、一時ファイル、クラッシュダンプ、シェーダーキャッシュ、ごみ箱。どれも推定ではなく実測です。既定では何もチェックされず、開かれているファイルは強制せずに飛ばし、再解析ポイントは決してたどりません。

  • あなた自身のファイルは別扱い

    古いダウンロードや、アンインストール済みソフトが残したフォルダーは、サイズと経過期間を添えて 1 件ずつ並び、1 件ずつチェックし、ごみ箱へ送られます — いきなり削除はしません。その判定はあくまで推測であり、Hexnest はそう明言します。

  • 10 の言語を話す

    英語、トルコ語、ロシア語、簡体字中国語、ヒンディー語、ポルトガル語、日本語、ドイツ語、フランス語、韓国語が 1 つの実行ファイルに。言語もライト/ダークのテーマも、アプリを開いたまま即座に切り替わり、再起動は要りません。

フォーマット後のドライバー導入、手順どおりに

これこそ Hexnest が存在する理由となる道筋です。フォーマット前に費やす 5 分が、直後にマシンを使える状態にします。

フォーマットの前に — 5 分ほど

  1. Hexnest を実行して開きます: バックアップと復元付きで呼び戻すからです。
  2. クリックします: バックアップを作成。システム上のサードパーティ製ドライバーパッケージがすべて書き出されます。
  3. 1 つのファイルにまとめたい場合は ZIP に圧縮 にチェックを入れます。
  4. できあがったフォルダーと Hexnest.exe を 同じ USB メモリにコピーします。
  5. 必須ではありませんが便利です: フォルダー名を Drivers にして、次の場所の隣に置いてください: Hexnest.exe。Hexnest はそれを自動的にローカルのドライバーリポジトリとして登録します。設定は不要です。

フォーマットの後で

  1. USB メモリを挿して実行します: Hexnest.exe --rescue。Windows Update には一切接続せず、ローカルのソースだけを使います。
  2. こちらへ: バックアップと復元 → 復元、または フォルダーから復元を選び、バックアップを指定します。各パッケージがドライバーストアに追加され、対応するデバイスに割り当てられます。
  3. ネットワークアダプターのドライバーが動くようになったら、次を押します: 調べる付きで呼び戻すからです。
  4. ダッシュボード → フォーマット後の復旧 。まだ足りていないものが、今度は Windows Update からキューに入ります。
  5. 再起動を求められたら受け入れてください。Hexnest はログイン時に戻ってきて、キューの残りを片づけます。

バックアップも、インターネットも、準備も何もない場合は? こちらを使ってください: ダッシュボード → ハードウェアレポート 。すべてのハードウェア ID をテキストファイルに書き出し、それを動くコンピューターへ持って行き、メーカーから正しいパッケージをダウンロードして展開し、フォルダーを持ち帰って次の方法でインストールします: フォルダーから復元。まずネットワークアダプターから始めてください。それさえ動けば、あとは Windows Update が引き受けます。

コマンドライン

Hexnest.exe                 # 通常の起動
Hexnest.exe --rescue        # オフラインの復旧モード (--offline と同じ)
Hexnest.exe --resume        # 中断したキューをすぐ続ける

同じ数字ではない 2 つの数字

モニタのページは、たいていのツールが黙って間違えていることに気を配っています。マシン全体が転送した量と、1 つのプログラムが転送した量は測り方が異なり、合計はぴったり一致しません。だから Hexnest は 2 つを分けて示し、その理由も書いています。

同じ誠実さは温度にも当てはまります。Windows には汎用の温度 API がありません。あるのは、OS 自身のファン制御のためにファームウェアが宣言する ACPI サーマルゾーンだけで、デスクトップ機の多くは 1 つも宣言していません。コアごと・GPU ごとの本当の値は SMBus 経由でベンダー製チップから取るもので、署名済みのカーネルドライバーが必要です。HWiNFO のようなツールがそれを入れるのはそのためです。Hexnest はページに数字を描くためだけにカーネルドライバーを入れることはしません。だからセンサーがないマシンでは、カードがそう伝えます。

クリーンアップツールがたいてい間違える 2 つのこと

スタートアッププログラムの無効化は、削除であってはならない。 Windows は有効フラグを専用のキーに保持しており、 StartupApproved、Hexnest が書き込むのはそれだけです — Run の値も、スタートアップフォルダーのショートカットも、まったくそのまま残ります。だから項目を戻せば元のコマンドラインがバイト単位で復元され、タスクマネージャーと Hexnest は常に一致し、あとで Hexnest を消してもスタートアップ項目が半分なくなることはありません。楽な実装 — 値を消して Hexnest 自身の設定に覚えておく — は、他人のソフトウェアにとって Hexnest を黙って不可欠なものにしてしまいます。

クリーナーが、あなたのファイルについて推測で動いてはならない。 キャッシュは全部か無かでかまいません。自分で再生成されるからです。あなたのファイルは違います。古いダウンロードや、アンインストール済みソフトが残したフォルダーは、サイズと経過期間を添えて 1 件ずつ並び、1 件ずつチェックし、削除ではなくごみ箱へ送られます。残骸の判定は本当に推測です — インストール済みの全プログラム、実行中の全プログラム、Program Files の中身すべてと突き合わせ、6 か月間書き込みがないことを条件にしています — そして行にも推測だと書いてあります。ページ上のサイズはすべて推定ではなく実測なので、合計は本当に戻ってくる容量です。しかもページを開いた時点では、何ひとつチェックされていません。

そしてメモリのボタン。 「RAM を解放」する類のページは、プロセスのワーキングセットをディスクへ追い出します。使用中の物理メモリは確かに減ります — が、そのプログラムをまた使った瞬間に Windows はそのページを読み戻すので、何も速くならず、追い出されたプログラムは一時的に遅くなります。大量のメモリを一度に要するものを起動する直前には意味がありますが、それ以外では意味がありません。Hexnest はボタンの隣に、そう書いています。

Hexnest の比較 — 見劣りする点も含めて

ドライバー更新ツールの評判は悪く、その多くは自業自得です。40 個の問題を見つける無料スキャン、修正の手前に置かれた課金の壁、常駐サービス、そして仲間を連れてくるインストーラー。Hexnest は逆向きに作られています。とはいえ、いくつかの具体的な点では商用ツールに劣ります。それらは埋もれさせず、ここに並べてあります。

正直に言う注意点。 Hexnest は コード署名されていません。そのため初回起動時に SmartScreen と Smart App Control が警告します。対処は、ファイルを盲信するのではなく、公開された SHA-256 を検証することです。管理者権限が必要で、64 ビットの Windows 10 1607 以降でしか動かず、.NET ランタイムを丸ごと内包しているため実行ファイルは大きく、Windows が並列実行を認めないためインストールは 1 件ずつになります。ドライバーの導入には本質的なリスクがあります。復元ポイントの設定は有効のままにし、バックアップを取り、リポジトリの免責事項を読んでください。

Hexnest は本当に無料ですか?

はい。Hexnest は MIT ライセンスで公開され、ソースコードはすべて GitHub にあります。有料版も、体験版も、支払い後に解除される機能も、広告も、同梱されるサードパーティ製ソフトもありません。スキャンもインストールも同じ 1 つの製品です。

.NET や Visual C++ 再頒布可能パッケージのインストールは必要ですか?

いいえ。.NET 8 ランタイムはまるごと Hexnest.exe の中に自己完結型の単一ファイルとして入っており、WPF は vcruntime140_cor3.dll と msvcp140_cor3.dllの専用コピーを自前で持っています。必要なのは 64 ビットの Windows 10 バージョン 1607 (ビルド 14393) 以降だけです。実行ファイルが約 65 MB あるのも、そのためです。

なぜ SmartScreen やウイルス対策ソフトが Hexnest を警告するのですか?

Hexnest は コード署名されていません。コード署名証明書にはお金がかかるからです。Windows SmartScreen と Smart App Control は、評判が積み上がっていない未署名の実行ファイルすべてに警告を出します。しかも、管理者として動き、ドライバーを入れ、タスクを登録する単一ファイルのアプリは、ヒューリスティックなスキャナーにはマルウェアそのものに見えます。

誠実な対処は、ダウンロードを検証することです。次を実行し、 Get-FileHash .\Hexnest.exe -Algorithm SHA256 その結果を、リリースと一緒に公開されている Hexnest.exe の中の checksums.txt の行と比べてください。一致すれば、そのファイルは公開されたものとバイト単位で同一です。自分でソースからビルドすることもできます。

インターネットなしで、フォーマット後にドライバーを入れられますか?

はい、そのために作られました。フォーマットの前に バックアップと復元 でサードパーティ製ドライバーパッケージをすべて書き出し、そのフォルダーと Hexnest.exe を同じ USB メモリにコピーします。フォーマットの後は、次で起動してください: Hexnest.exe --rescue。Windows Update には一切接続せず、ローカルのソースだけを使います。

次の名前のフォルダー: Drivers を、次の隣に置くと: Hexnest.exe 、自動的にローカルのドライバーリポジトリとして登録されます。自分で展開したメーカー配布のドライバーフォルダーでも同じように使えます。INF ファイルを再帰的に照合するからです。

不具合を起こしたドライバーを元に戻せますか?

はい、3 通りあります。

  1. Hexnest は置き換える直前のパッケージを書き出し、そのパスを履歴に記録します。だから次の方法で入れ直せます: フォルダーから復元付きで呼び戻すからです。
  2. セッション最初のインストール前にドライバー種別のシステム復元ポイントを作ります。Windows のシステムの復元ウィザード (rstrui.exe) から使えます。
  3. Windows 自身の ドライバーを元に戻す ボタンも、デバイスマネージャーで Hexnest とは無関係に使えます。

再起動のあと、本当に続きから再開しますか?

はい。キューは状態が変わるたびにアトミックに session.json へ書き出され、Hexnest はログイン時に起動するタスクを次の名前で登録します: Hexnest\ResumeSession。タスクスケジューラが使えない場合は HKLM の RunOnce 値にフォールバックします。次回ログイン時にそのタスクが Hexnest を --resume 付きで起動し直し、残りの処理が続きます。1 つのセッションが耐えられる再起動は最大 10 回で、キューが終わるとタスクも RunOnce の値も削除されます。

なぜ Hexnest には管理者権限が必要なのですか?

ドライバーのインストールは特権が要る操作です。 pnputilでドライバーストアにパッケージを追加・書き出しすること、Windows Update のインストーラーを動かすこと、 srclient.dll 経由でシステム復元ポイントを作ること — どれも昇格されたトークンを必要とし、再開用のタスクは HKLM に登録されます。Hexnest はキューの途中で「アクセスが拒否されました」と失敗するのではなく、アプリケーションマニフェストで最初に昇格を要求します。

スタートアッププログラムを無効にすると、何か削除されますか?

いいえ。Windows は有効フラグを別のキー — ...\CurrentVersion\Explorer\StartupApproved\Run とその 2 つの兄弟 — に保持しており、Hexnest が書き込むのはそれだけです。 Run の値も、スタートアップフォルダーのショートカットも、まったくそのまま残るので、項目を戻せば元のコマンドラインがバイト単位で復元されます。

つまり、タスクマネージャーと Hexnest は常に一致し、あとで Hexnest を消してもスタートアップ項目が半分なくなることはありません。

クリーンアップは安全ですか?

安全になるよう作ってあります。しかも「信じてください」ではなく、設計でどう担保しているかを示します:

  • 既定では何もチェックされていません。 ページは合計ゼロの状態で開きます。
  • パスはすべて文字列ではなく既知フォルダー API から取得し、個々の削除はその直前に、自分のカテゴリのルート配下かどうかを再確認します。
  • 再解析ポイントは決してたどりません — %LOCALAPPDATA% はジャンクションだらけで、そこへ入り込むことこそ「キャッシュを消す」機能が誰かのドキュメントを消してしまう経路です。
  • 開かれているファイルは強制せずに飛ばし、飛ばした数を報告します。
  • あなた自身のファイルは決して一括選択されず、ごみ箱へ送られます。

「メモリを解放」は実際に効果がありますか?

その瞬間の物理メモリを解放します。それだけです。各プロセスのワーキングセットをページファイルへ追い出すよう Windows に頼むので、使用中メモリは確かに減ります — ただしそのページは消えたのではなくディスクにあり、プログラムがそのメモリに触れた瞬間に Windows は読み戻します。使われていないメモリは無駄なメモリではありません。Windows はもともと、それを使える状態に保っていたのです。

つまり性能向上の機能ではなく、Hexnest もそう称してはいません。大きな確保をいきなり行うものを起動する直前や、リークしているプログラムが実際どれだけ抱えているかを見るときに役立ちます。このボタンを持つ他のツールは、どれも違うことを主張します。

なぜ温度カードは「センサーがない」と言うのですか?

そのマシンには、Windows が読めるセンサーが実際にないからです。ドライバーなしで Windows が公開する温度は、ファームウェアが自身のファン制御のために宣言する ACPI サーマルゾーンだけで、デスクトップのマザーボードには 1 つも宣言しないものが非常に多くあります。コアごとや GPU の温度は SMBus 経由でベンダー製のセンサーチップから取るもので、署名済みのカーネルドライバーが必要です — HWiNFO や Open Hardware Monitor が入れているのがそれです。Hexnest は数字を埋めるためだけにカーネルドライバーを入れることはしないので、推測する代わりに「センサーがない」と伝えます。

なぜプログラム別の通信量はマシン全体の合計になりませんか?

2 つの数字は出どころが違い、どちらも正しいのです。マシン全体はネットワークアダプター自身のバイトカウンターの合計なので、TCP・UDP・QUIC・ブロードキャストのすべてを含みます。アプリ別は Windows の TCP 接続統計 (ESTATS) から取っており、これはカーネルドライバーなしに Windows が提供する唯一のプロセス別バイトカウンターで、TCP しか対象にしません。ビデオ通話、ゲームの通信の大半、DNS が 1 つ目の数字にあって 2 つ目にないのはそのためです。Hexnest は黙って少なく報告するのではなく、ページ上でそう説明します。

Hexnest はバックグラウンドで自動更新しますか?

1 日 1 回確認し、知らせるだけです。次の場所でオンにしない限り、何もインストールしません: 設定 → 更新。オンにした場合も、ダウンロードはリリースの checksums.txt と照合されたうえで、Hexnest の終了時にだけ差し替えられます — ドライバーのキューが動いている最中には決してありません。オフラインモードと復旧モードでは、確認もインストールも完全に省かれます。確認自体を完全に切ることもできますし、その場合も「バージョン情報」ページのボタンは使えます。

モニタはバックグラウンドサービスですか?

いいえ。どちらのモニタもページを開くまで何も計測せず、離れた瞬間に止まります。Hexnest はサービスもドライバーもスタートアップ項目もインストールしません — 登録するのは、中断したドライバーのキューを再開するログインタスクだけで、それもキューが終われば自分で消えます。

Hexnest は何かデータを集めますか?

いいえ。テレメトリも、利用統計も、デバイス識別子もありません。マシンの外へ出るのは、ちょうど 2 つだけです。1 つは Windows Update への問い合わせで、Windows 自身の Windows Update エージェント経由で Microsoft に直接届き、オフラインモードや復旧モードでは完全に省かれます。もう 1 つは GitHub Releases API へのリクエストで、 更新を確認を押したときに 1 回、自動確認を有効にしていれば 1 日 1 回です。どちらもあなたのマシンについて何も送りません。ごく普通の匿名の HTTPS GET です。モニタのページはどこへも何も送りません。表示される数字はすべてローカルで読み取られ、コンピューターの外へ出ることはありません。それ以外はすべて、あなたのマシンの %ProgramData%\Hexnest に留まります。

Hexnest を入手する

実行ファイルをダウンロードし、好きな場所に置いてダブルクリックするだけです。削除するときはファイルを消し、必要ならフォルダーも消してください: %ProgramData%\Hexnest 。キューが終わっていれば、レジストリには何も残りません。
