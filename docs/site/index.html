One window for what your computer is doing, on Windows and on a Mac

Hexnest shows you live what the machine and every program on it are costing in processor time, memory and bandwidth, what starts itself at login, and where your disk space actually went — measured, never estimated. On Windows it is also a full driver updater: it scans every device, installs the missing and outdated drivers from the Windows Update catalog or from a folder on a USB stick, keeps going after the restarts a driver install needs, and can put your old drivers back with no internet at all.

Windows 10 1607+ and Windows 11 · macOS 12 Monterey or newer · 64-bit, Apple silicon and Intel · MIT licensed

Recently added 1.3.0

Everything below is in the shipping application. There is no roadmap section here pretending to be a feature list.

  • Startup Programs

    Every autostart entry Windows will run at logon — the registry Run keys and both Startup folders — with a switch each. Disabling writes the same setting Task Manager writes, so the two always agree and the original command line is never deleted. Entries pointing at a file that no longer exists are flagged; Windows retries those at every logon and fails silently.

  • Clean Up

    Temporary files, thumbnail and icon caches, seven browsers, the Windows Update download cache, crash dumps, shader caches, servicing logs and the Recycle Bin. Every size is measured rather than estimated, so the number next to a box is the space that will actually come back — and nothing is ticked for you.

  • Your files stay yours

    Old downloads and folders left behind by uninstalled software are never bulk-selected. They are listed one by one with a size and an age, ticked individually, and sent to the Recycle Bin rather than deleted — because the leftover detection is a guess, and the page says so.

  • System Monitor

    Processor load with a bar for every logical core, a memory breakdown down to cached and committed bytes, every temperature sensor the firmware exposes, storage capacity with live read and write throughput, and battery state — plus a table of every running program and what it is costing.

  • Network Monitor

    Live download and upload for the whole machine, totals for this session and since Windows started, every adapter with its address and link speed, and a per-application table showing which program is using the connection, how fast, and how many connections it is holding open.

  • Automatic updates

    Hexnest now asks GitHub once a day whether a newer release exists and tells you on the menu. Downloading and installing stays off by default, and even when you switch it on the verified file is only swapped in as the application closes — never in the middle of a driver queue.

  • Five languages

    English, Turkish, Russian, Simplified Chinese and Hindi, all built into the single executable and switchable without a restart. A JSON file dropped next to Hexnest.exe still adds or corrects a translation with no rebuild.

The problem it was built for

You have just reinstalled Windows. Device Manager is full of yellow exclamation marks, the resolution is wrong, there is no sound and — worst of all — no internet, because the network adapter has no driver either. You need the internet to download a driver, and a driver to reach the internet.

Hexnest breaks that loop from a single window: it enumerates the hardware, matches it against drivers it can actually reach, and installs them. When there is no network at all, it installs from a folder you brought with you.

What Hexnest does

Every one of these is in the shipping application — there is no roadmap section pretending to be a feature list.

  • Scans every device

    Enumerates all present PnP devices through SetupAPI and CfgMgr32 rather than WMI, so it works on a machine that was formatted five minutes ago or whose WMI repository is broken.

  • Finds the missing drivers

    Reads live Configuration Manager problem codes. Code 28, 1 and 19 mean "no driver"; 22 is a disabled device and 14 is one waiting for a restart. Filters let you look at problem devices, driverless devices or devices running a generic driver.

  • Uses the Windows Update driver catalog

    Talks to Microsoft Update through the Windows Update Agent COM API that already ships with Windows. No extra service to install, no third-party driver mirror in the middle.

  • Installs from a USB stick, offline

    Parses the INF packages in any folder — a USB stick, a network share, a Hexnest backup or a vendor download you extracted — and matches them to your hardware ids.

  • Downloads in parallel, installs one at a time

    Three concurrent downloads by default, configurable from one to eight. Installs are serialized on purpose: Windows Update returns WU_E_OPERATIONINPROGRESS for a second concurrent install and the PnP subsystem serializes anyway.

  • Survives the reboots

    Queue state is written to session.json after every change and a logon-triggered scheduled task brings Hexnest back with --resume, so a ten-driver queue that needs three restarts finishes itself.

  • Backs up before it changes anything

    A driver-type system restore point before the first install of a session, and an export of each driver package immediately before it is replaced, with the path recorded in the history entry.

  • Backs up and restores your whole driver set

    Exports every third-party driver package with pnputil /export-driver into a folder or a ZIP, and restores with pnputil /add-driver /subdirs /install. Microsoft's in-box drivers are deliberately skipped — Windows reinstalls those itself.

  • Writes a hardware report

    Every device and hardware id in a plain text file, so you can carry it on a USB stick to a working computer and look the drivers up by hand when nothing else is available.

  • Keeps an honest history

    A permanent record of every driver operation as one JSON object per line, filterable by outcome and exportable to CSV in a click, plus a live diagnostic log with a copy button that includes the version and OS header.

  • Verifies its own updates

    The built-in updater compares the download against the SHA-256 in the release's checksums.txt, and refuses to install anything when the checksum is missing or does not match. It never updates silently in the background.

  • Shows what the machine is doing

    A live panel for processor load per logical core, memory down to cached and committed bytes, every temperature sensor the firmware actually exposes, storage capacity with real read and write throughput, and battery state. Nothing is sampled until you open the page, and it stops the moment you leave it.

  • Shows what each program costs

    Processor share, working set, private bytes, disk throughput and thread count for every running process, measured the same way Task Manager measures them. Sortable, searchable and pausable.

  • Shows where the bandwidth goes

    Live download and upload for the whole machine from the adapters’ own counters, and per-application traffic from Windows’ TCP connection statistics — no kernel driver, no packet capture, no third-party service.

  • Keeps itself up to date

    One request a day to the GitHub Releases API tells you when a new version exists. Automatic download and install is opt-in, verified against SHA-256, and only ever applied as Hexnest closes.

  • Manages what starts with Windows

    Every autostart entry from the registry Run keys and both Startup folders, with a switch each. Disabling writes the same StartupApproved value Task Manager writes, so nothing is deleted and the two tools always agree — and uninstalling Hexnest never leaves the machine missing half its startup programs.

  • Measures what is taking up space

    Caches, temporary files, crash dumps, shader caches and the Recycle Bin, each one measured rather than estimated. Nothing is ticked by default, files that are open are skipped rather than forced, and reparse points are never followed.

  • Keeps your own files separate

    Old downloads and folders left behind by uninstalled software are listed one by one with a size and an age, ticked individually, and sent to the Recycle Bin — never deleted outright, because that detection is a guess and Hexnest says so.

  • Speaks five languages

    English, Turkish, Russian, Simplified Chinese and Hindi, all inside the one executable. The language and the dark or light theme both switch instantly while the application is open, with no restart.

Installing drivers after a format, step by step

This is the walkthrough Hexnest exists for. The five minutes you spend before the format are what make the machine usable immediately afterwards.

Before the format — about five minutes

  1. Run Hexnest and open Backup & Restore.
  2. Click Create backup. Every third-party driver package on the system is exported.
  3. Tick Compress as ZIP if you want a single file.
  4. Copy the resulting folder and Hexnest.exe onto the same USB stick.
  5. Optional but useful: name the folder Drivers and keep it next to Hexnest.exe. Hexnest then registers it as a local driver repository automatically, with no configuration.

After the format

  1. Plug the stick in and run Hexnest.exe --rescue. Windows Update is never contacted; only local sources are used.
  2. Go to Backup & Restore → Restore, or Restore from folder, and pick your backup. Every package is added to the driver store and bound to its devices.
  3. Once the network adapter has a working driver, press Scan.
  4. Dashboard → Post-format recovery queues everything still missing, from Windows Update this time.
  5. Accept the restart when it is asked for. Hexnest comes back at logon and finishes the rest of the queue.

No backup, no internet, nothing prepared? Use Dashboard → Hardware report to write every hardware id to a text file, carry it to a working computer, download the right packages from the vendor, extract them, bring the folders back and install them with Restore from folder. Start with the network adapter; once that works, Windows Update handles the rest.

Command line

Hexnest.exe                 # normal launch
Hexnest.exe --rescue        # offline rescue mode (same as --offline)
Hexnest.exe --resume        # continue an interrupted queue straight away

Two numbers that are not the same number

The monitor pages are careful about something most tools quietly get wrong. What the whole machine transfers and what a single program transfers are measured in two different ways, and they do not add up to exactly the same total — so Hexnest reports them separately and says why.

The same honesty applies to temperature. Windows has no general-purpose temperature API; what exists is the ACPI thermal zone the firmware declares for the operating system’s own fan control. Many desktops declare none at all. Real per-core and per-GPU readings come from a vendor chip over an SMBus and need a signed kernel driver, which is why tools like HWiNFO install one. Hexnest will not install a kernel driver to draw a number on a page, so when the machine has no sensor the card says so.

The two things a clean-up tool usually gets wrong

Disabling a startup program should not delete it. Windows keeps the enabled flag in its own key, StartupApproved, and that is the only thing Hexnest writes — the Run value or the Startup-folder shortcut is left exactly where it is. So switching an entry back on restores the original command line byte for byte, Task Manager and Hexnest always agree with each other, and deleting Hexnest later never leaves the machine missing half its startup programs. The easier implementation — delete the value, remember it in Hexnest's own settings — quietly makes Hexnest load-bearing for somebody else's software.

A cleaner should not guess with your files. Caches are all-or-nothing, because a cache rebuilds itself. Your own files are not: old downloads and folders left behind by uninstalled software are listed one at a time with their size and age, ticked one at a time, and sent to the Recycle Bin rather than deleted. The leftover detection is genuinely a guess — it checks the folder against every installed program, every running program and everything in Program Files, and requires six months of no writes — and the row says it is a guess. Every size on the page is measured rather than estimated, so the total is the space that will actually come back, and nothing at all is ticked when the page opens.

And the memory button. "Free up RAM" pages process working sets out to disk. Physical memory in use really does drop — and Windows reads those pages straight back the moment the programs are used again, so it makes nothing faster and briefly makes the trimmed programs slower. It is worth doing immediately before something that needs a lot of memory at once, and not otherwise. Hexnest says that on the page, next to the button.

How Hexnest compares — and where it falls short

Driver updaters have a bad reputation, and it is mostly earned: a free scan that finds forty problems, a paywall in front of the fix, a resident service, and an installer that brings friends. Hexnest is built the other way round. It is also worse than commercial tools in a few specific ways, and those are listed here rather than buried.

The honest small print. Hexnest is not code-signed, so SmartScreen and Smart App Control will warn you on first run; the fix is to verify the published SHA-256 rather than to trust the file blindly. It needs administrator rights, it only runs on 64-bit Windows 10 1607 or newer, the executable is large because the whole .NET runtime is inside it, and installs run one at a time because Windows will not do them in parallel. Installing drivers is inherently risky: leave the restore-point setting on, keep backups, and read the disclaimer in the repository.

Frequently asked questions

The full list, including the technical questions, is in docs/FAQ.md.

Is Hexnest really free?

Yes. Hexnest is released under the MIT licence and the full source code is on GitHub. There is no paid tier, no trial, no feature that unlocks after payment, no advertising and no bundled third-party software. The scan and the installs are the same product.

Do I need to install .NET or the Visual C++ Redistributable?

No. The entire .NET 8 runtime is inside Hexnest.exe as a self-contained single-file publish, and WPF carries its own private copies of vcruntime140_cor3.dll and msvcp140_cor3.dll. The only requirement is 64-bit Windows 10 version 1607 (build 14393) or newer. That is also why the executable is around 65 MB.

Why does SmartScreen or my antivirus warn about Hexnest?

Hexnest is not code-signed, because a code-signing certificate costs money. Windows SmartScreen and Smart App Control show a warning for any unsigned executable that has not built up reputation, and a single-file app that runs as administrator, installs drivers and registers a scheduled task looks like malware to a heuristic scanner.

The honest mitigation is to verify the download. Run Get-FileHash .\Hexnest.exe -Algorithm SHA256 and compare the result with the Hexnest.exe line in the checksums.txt published with the release. A match means the file is byte-for-byte the published one. You can also build it yourself from source.

Can Hexnest install drivers after a format with no internet?

Yes, and that is what it was built for. Before the format, use Backup & Restore to export every third-party driver package, then copy that folder and Hexnest.exe onto the same USB stick. After the format, start Hexnest.exe --rescue: Windows Update is never contacted and only local sources are used.

A folder named Drivers next to Hexnest.exe is registered automatically as a local driver repository. Any vendor driver folder you extracted yourself works too, because its INF files are matched recursively.

Can I roll back a driver that breaks something?

Yes, in three ways.

  1. Hexnest exports the package it is about to replace and records the path in the history entry, so you can reinstall it with Restore from folder.
  2. It creates a driver-type system restore point before the first install of a session, which you can use through the Windows System Restore wizard (rstrui.exe).
  3. Windows' own Roll Back Driver button in Device Manager keeps working independently of Hexnest.

Does Hexnest really continue after a reboot?

Yes. The queue is written atomically to session.json on every state change, and Hexnest registers a logon-triggered scheduled task called Hexnest\ResumeSession, falling back to an HKLM RunOnce value when Task Scheduler is unavailable. At the next logon the task relaunches Hexnest with --resume and the remaining jobs continue. A session survives at most ten restarts, and the task and RunOnce value are removed when the queue finishes.

Why does Hexnest need administrator rights?

Installing a driver is a privileged operation. Adding packages to or exporting them from the driver store with pnputil, driving the Windows Update installer and creating a system restore point through srclient.dll all require an elevated token, and the resume task is registered under HKLM. Hexnest asks for elevation up front in its application manifest rather than failing with "access denied" in the middle of a queue.

Does disabling a startup program delete anything?

No. Windows keeps the enabled flag in a separate key — ...\CurrentVersion\Explorer\StartupApproved\Run and its two siblings — and that is the only thing Hexnest writes. The Run value, or the shortcut in the Startup folder, stays exactly where it is, so switching the entry back on restores the original command line byte for byte.

It also means Task Manager and Hexnest agree with each other, and that deleting Hexnest later never leaves the machine missing half its startup programs.

Is the clean-up safe?

It is built to be, and the design says how rather than asking you to trust it:

  • Nothing is ticked by default. The page opens with a total of zero.
  • Every path comes from a well-known folder API, not from a string, and each individual deletion is re-checked against its own category's roots immediately before it happens.
  • Reparse points are never followed — %LOCALAPPDATA% is full of junctions, and walking into one is how a "clear the cache" feature ends up deleting somebody's documents.
  • Files that are open are skipped rather than forced, and the number skipped is reported.
  • Your own files are never bulk-selected, and they go to the Recycle Bin.

Does "free up memory" actually do anything?

It frees physical memory right now, and that is all it does. It asks Windows to page each process' working set out to the page file, so memory in use genuinely drops — and those pages are not gone, they are on disk, and Windows reads them straight back the moment the program touches that memory again. Unused memory is not wasted memory; Windows was already keeping it available.

So it is not a performance feature and Hexnest does not present it as one. It is useful immediately before starting something that needs a large allocation, or to see how much a leaking program is really holding. Every other tool with this button claims otherwise.

Why does the temperature card say there is no sensor?

Because on that machine there is not one Windows can read. The only temperature Windows exposes without a driver is the ACPI thermal zone the firmware declares for its own fan control, and a great many desktop motherboards declare none. Per-core and GPU temperatures come from a vendor sensor chip over an SMBus, which needs a signed kernel driver — that is what HWiNFO and Open Hardware Monitor install. Hexnest will not install a kernel driver to fill in a number, so it tells you the sensor is missing instead of guessing.

Why does per-program network usage not add up to the machine total?

The two figures come from different places, and both are correct. The machine total is the sum of the network adapters’ own byte counters, so it includes everything: TCP, UDP, QUIC, broadcast. The per-application figure comes from Windows’ TCP connection statistics (ESTATS), which is the only per-process byte counter Windows offers without a kernel driver — and it covers TCP only. Video calls, most game traffic and DNS are therefore in the first number and not in the second. Hexnest says so on the page rather than quietly under-reporting.

Does Hexnest update itself in the background?

It checks, once a day, and tells you. It does not install anything unless you turn that on in Settings → Updates, and even then the download is verified against the release’s checksums.txt and only swapped in as Hexnest closes — never while a driver queue is running. Both the check and the install are skipped entirely in offline and rescue mode. You can also turn the check off completely; the button on the About page keeps working.

Is the monitor a background service?

No. Neither monitor samples anything until you open its page, and both stop the moment you navigate away. Hexnest still installs no service, no driver and no startup entry — the only thing it ever registers is the logon task that resumes an interrupted driver queue, and that removes itself when the queue finishes.

Does Hexnest collect any data?

No. There is no telemetry, no usage statistics and no device identifiers. Exactly two things ever leave the machine: Windows Update queries, which go straight to Microsoft through Windows' own Windows Update Agent and are skipped entirely in offline or rescue mode, and a requests to the GitHub Releases API — one when you press Check for updates, and one a day from the automatic check if you leave it on. Neither sends anything about your machine; they are ordinary anonymous HTTPS GETs. The monitor pages send nothing anywhere: every number on them is read locally and never leaves the computer. Everything else stays in %ProgramData%\Hexnest on your own machine.

Get Hexnest

Download the executable, put it wherever you like and double-click it. To remove it, delete the file and optionally the %ProgramData%\Hexnest folder — nothing is left in the registry once a queue has finished.
