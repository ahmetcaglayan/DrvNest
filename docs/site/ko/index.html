컴퓨터가 무엇을 하고 있는지, Windows에서도 Mac에서도 창 하나로

Hexnest는 이 컴퓨터와 그 위의 모든 프로그램이 프로세서 시간, 메모리, 대역폭을 얼마나 쓰고 있는지, 로그인할 때 무엇이 스스로 시작되는지, 디스크 공간이 실제로 어디로 갔는지를 실시간으로 보여 줍니다. 추정이 아니라 실측입니다. Windows에서는 본격적인 드라이버 업데이트 도구이기도 합니다. 모든 장치를 검사하고, 빠졌거나 오래된 드라이버를 Windows Update 카탈로그나 USB 메모리의 폴더에서 설치하며, 드라이버 설치에 필요한 재시작을 넘겨 가며 작업을 이어 가고, 인터넷이 전혀 없어도 예전 드라이버를 되돌려 놓을 수 있습니다.

최근 추가 1.5.0

아래 내용은 모두 배포 중인 애플리케이션에 들어 있습니다. 기능 목록인 척하는 로드맵 항목은 없습니다.

  • 시작프로그램

    Windows가 로그인할 때 실행하는 모든 자동 시작 항목 — 레지스트리의 Run 키와 두 개의 시작프로그램 폴더 — 을 항목마다 스위치 하나로. 사용 안 함으로 바꾸면 작업 관리자가 쓰는 것과 같은 설정을 쓰기 때문에 두 도구가 항상 일치하고, 원래 명령줄은 절대 지워지지 않습니다. 더 이상 없는 파일을 가리키는 항목에는 표시가 붙습니다. Windows는 로그인할 때마다 그것을 다시 시도하고 조용히 실패합니다.

  • 정리

    임시 파일, 축소판과 아이콘 캐시, 브라우저 일곱 종, Windows Update 다운로드 캐시, 크래시 덤프, 셰이더 캐시, 서비스 로그, 그리고 휴지통. 모든 크기는 추정이 아니라 실측이라 상자 옆의 숫자가 실제로 되돌아올 공간입니다 — 게다가 대신 체크해 두는 항목도 없습니다.

  • 당신의 파일은 당신 것입니다

    오래된 다운로드와 제거된 소프트웨어가 남긴 폴더는 절대 한꺼번에 선택되지 않습니다. 크기와 경과 기간과 함께 하나씩 나열되고, 하나씩 체크하며, 삭제가 아니라 휴지통으로 보내집니다 — 남은 파일 판정은 어디까지나 추측이고, 페이지도 그렇게 말합니다.

  • 시스템 모니터

    논리 코어마다 막대 하나로 보여 주는 프로세서 부하, 캐시된 바이트와 커밋된 바이트까지 나눈 메모리, 펌웨어가 공개하는 모든 온도 센서, 실시간 읽기·쓰기 처리량이 함께 나오는 저장 장치 용량, 배터리 상태 — 여기에 실행 중인 모든 프로그램과 그 부하를 담은 표까지.

  • 네트워크 모니터

    컴퓨터 전체의 실시간 다운로드와 업로드, 이번 세션과 Windows 시작 이후의 합계, 주소와 링크 속도가 함께 나오는 모든 어댑터, 그리고 어느 프로그램이 연결을 얼마나 빠르게 쓰고 몇 개의 연결을 열어 두고 있는지 보여 주는 앱별 표.

  • 자동 업데이트

    Hexnest는 이제 하루에 한 번 GitHub에 새 릴리스가 있는지 묻고 메뉴로 알려 줍니다. 내려받기와 설치는 기본으로 꺼져 있고, 켜더라도 검증된 파일은 애플리케이션이 닫힐 때에만 교체됩니다 — 드라이버 대기열 중간에는 절대 아닙니다.

  • 열 개 언어

    영어, 튀르키예어, 러시아어, 중국어 간체, 힌디어, 포르투갈어, 일본어, 독일어, 프랑스어, 한국어가 모두 하나의 실행 파일 안에 들어 있고 재시작 없이 전환됩니다. Hexnest.exe 옆에 JSON 파일을 놓으면 다시 빌드하지 않고도 번역을 더하거나 고칠 수 있습니다.

  • 배터리 및 전원

    Windows에 대응하는 페이지가 없는 macOS 전용 페이지입니다. 질문 자체가 노트북의 것이기 때문입니다. 충전 주기, macOS가 직접 알려 주는 최대 용량, 상태, 배터리 자체 온도 — 그 아래에는 Mac을 깨어 있게 하는 각 프로세스와 그 어서션, 유지 시간. 타이머가 아니라 페이지를 열 때 읽습니다. 매초 측정하는 페이지는 배터리 이야기를 하려고 배터리를 쓰게 되기 때문입니다.

실제 화면

배포 중인 애플리케이션에서 찍은 진짜 스크린샷으로, Windows 11 노트북에서 촬영했습니다. Hexnest.exe --capture로 빌드 자체에서 다시 만들기 때문에 내용이 낡을 수 없습니다.

이 도구가 만들어진 이유

Windows를 막 다시 설치했습니다. 장치 관리자는 노란 느낌표로 가득하고, 해상도는 엉망이고, 소리도 안 나고 — 무엇보다 인터넷이 안 됩니다. 네트워크 어댑터에도 드라이버가 없기 때문입니다. 드라이버를 받으려면 인터넷이 필요하고, 인터넷에 닿으려면 드라이버가 필요합니다.

Hexnest는 그 순환을 창 하나에서 끊습니다. 하드웨어를 열거하고, 실제로 닿을 수 있는 드라이버와 맞춰 보고, 설치합니다. 네트워크가 전혀 없을 때는 당신이 들고 온 폴더에서 설치합니다.

Hexnest가 하는 일

이 가운데 어느 것도 예정이 아니라 배포 중인 애플리케이션에 들어 있습니다 — 기능 목록인 척하는 로드맵 항목은 없습니다.

  • 모든 장치를 검사합니다

    존재하는 모든 PnP 장치를 WMI가 아니라 SetupAPI와 CfgMgr32로 열거합니다. 그래서 5분 전에 포맷한 컴퓨터에서도, WMI 저장소가 망가진 컴퓨터에서도 동작합니다.

  • 빠진 드라이버를 찾아냅니다

    구성 관리자의 문제 코드를 실시간으로 읽습니다. 코드 28, 1, 19는 “드라이버 없음”을 뜻하고, 22는 사용 안 함으로 설정된 장치, 14는 재시작을 기다리는 장치입니다. 필터로 문제 있는 장치, 드라이버 없는 장치, 일반 드라이버로 도는 장치를 나눠 볼 수 있습니다.

  • Windows Update 드라이버 카탈로그를 씁니다

    이미 Windows에 들어 있는 Windows Update 에이전트 COM API를 통해 Microsoft Update와 통신합니다. 따로 설치할 서비스도, 중간에 끼는 서드파티 드라이버 미러도 없습니다.

  • USB 메모리에서 오프라인으로 설치합니다

    어떤 폴더든 — USB 메모리, 네트워크 공유, Hexnest 백업, 직접 푼 제조사 배포판 — 그 안의 INF 패키지를 해석해 당신의 하드웨어 ID와 맞춰 봅니다.

  • 내려받기는 병렬로, 설치는 하나씩

    기본값은 동시 세 개, 하나에서 여덟까지 설정할 수 있습니다. 설치를 일부러 직렬로 하는 이유가 있습니다. Windows Update는 두 번째 동시 설치에 WU_E_OPERATIONINPROGRESS를 돌려주고, PnP 서브시스템도 어차피 직렬화합니다.

  • 재시작을 견뎌 냅니다

    대기열 상태는 바뀔 때마다 session.json 에 기록되고, 로그인 때 실행되는 예약 작업이 --resume과 함께 Hexnest를 다시 불러옵니다. 그래서 재시작이 세 번 필요한 열 개짜리 대기열도 스스로 끝까지 갑니다.

  • 무엇이든 바꾸기 전에 백업합니다

    세션의 첫 설치 전에 드라이버 형식의 시스템 복원 지점을 만들고, 각 드라이버 패키지는 교체되기 직전에 내보내며, 그 경로를 기록 항목에 남깁니다.

  • 드라이버 전체를 백업하고 복원합니다

    모든 서드파티 드라이버 패키지를 pnputil /export-driver 로 폴더나 ZIP에 내보내고, pnputil /add-driver /subdirs /install로 되돌립니다. Microsoft가 기본 제공하는 드라이버는 일부러 건너뜁니다 — 그건 Windows가 알아서 다시 설치합니다.

  • 하드웨어 보고서를 만듭니다

    모든 장치와 하드웨어 ID를 일반 텍스트 파일로 저장합니다. USB 메모리에 담아 동작하는 컴퓨터로 가져가면, 다른 방법이 전혀 없을 때 손으로 드라이버를 찾아볼 수 있습니다.

  • 정직한 기록을 남깁니다

    모든 드라이버 작업을 한 줄에 JSON 객체 하나씩으로 영구히 기록하고, 결과로 거르고, 한 번의 클릭으로 CSV로 내보낼 수 있습니다. 여기에 버전과 OS 헤더가 포함된 복사 단추가 달린 실시간 진단 로그까지.

  • 자기 자신의 업데이트를 검증합니다

    내장 업데이트 기능은 내려받은 파일을 릴리스의 checksums.txt에 있는 SHA-256과 비교하고, 체크섬이 없거나 맞지 않으면 아무것도 설치하지 않습니다. 백그라운드에서 조용히 업데이트하는 일은 결코 없습니다.

  • 컴퓨터가 무엇을 하는지 보여 줍니다

    논리 코어별 프로세서 부하, 캐시된 바이트와 커밋된 바이트까지 보이는 메모리, 펌웨어가 실제로 공개하는 모든 온도 센서, 실제 읽기·쓰기 처리량이 함께 나오는 저장 장치 용량, 배터리 상태를 실시간 패널로 보여 줍니다. 페이지를 열기 전에는 아무것도 측정하지 않고, 페이지를 떠나는 순간 멈춥니다.

  • 프로그램마다 얼마나 쓰는지 보여 줍니다

    실행 중인 모든 프로세스의 프로세서 점유율, 작업 집합, 개인 바이트, 디스크 처리량, 스레드 수를 작업 관리자와 같은 방식으로 잽니다. 정렬하고, 검색하고, 잠시 멈출 수 있습니다.

  • 대역폭이 어디로 가는지 보여 줍니다

    컴퓨터 전체의 실시간 다운로드와 업로드는 어댑터 자체의 카운터에서, 앱별 트래픽은 Windows의 TCP 연결 통계에서 가져옵니다 — 커널 드라이버도, 패킷 캡처도, 서드파티 서비스도 없습니다.

  • 스스로 최신 상태를 유지합니다

    하루 한 번 GitHub 릴리스 API에 보내는 요청이 새 버전이 나왔음을 알려 줍니다. 자동 내려받기와 설치는 선택 사항이고, SHA-256으로 검증되며, Hexnest가 닫힐 때에만 적용됩니다.

  • Windows와 함께 시작되는 것을 관리합니다

    레지스트리의 Run 키와 두 시작프로그램 폴더에 있는 모든 자동 시작 항목을 항목마다 스위치 하나로. 사용 안 함으로 바꾸면 작업 관리자가 쓰는 것과 같은 StartupApproved 값을 쓰기 때문에 아무것도 지워지지 않고 두 도구가 항상 일치합니다 — 그리고 Hexnest를 제거해도 시작프로그램이 절반쯤 사라지는 일은 없습니다.

  • 공간을 차지하는 것을 실제로 잽니다

    캐시, 임시 파일, 크래시 덤프, 셰이더 캐시, 휴지통을 하나하나 추정이 아니라 실측합니다. 기본으로 체크된 항목은 없고, 열려 있는 파일은 강제하지 않고 건너뛰며, 재분석 지점은 절대 따라가지 않습니다.

  • 당신의 파일은 따로 둡니다

    오래된 다운로드와 제거된 소프트웨어가 남긴 폴더는 크기와 경과 기간과 함께 하나씩 나열되고, 하나씩 체크하며, 휴지통으로 보내집니다 — 곧바로 삭제하지 않습니다. 그 판정은 추측이고, Hexnest는 그렇게 말합니다.

  • 열 개 언어를 씁니다

    영어, 튀르키예어, 러시아어, 중국어 간체, 힌디어, 포르투갈어, 일본어, 독일어, 프랑스어, 한국어가 모두 하나의 실행 파일 안에 있습니다. 언어도, 밝은 테마와 어두운 테마도 애플리케이션을 연 채로 즉시 바뀌며 재시작이 필요 없습니다.

포맷한 뒤 드라이버 설치하기, 단계별로

이것이 Hexnest가 존재하는 이유가 되는 과정입니다. 포맷 전에 쓰는 5분이, 그 직후에 컴퓨터를 바로 쓸 수 있게 만듭니다.

포맷하기 전 — 5분쯤

  1. Hexnest를 실행하고 여십시오: 백업 및 복원와 함께 다시 불러오기 때문입니다.
  2. 다음을 누르십시오: 백업 만들기. 시스템의 모든 서드파티 드라이버 패키지가 내보내집니다.
  3. 파일 하나로 묶고 싶다면 ZIP으로 압축 에 체크하십시오.
  4. 만들어진 폴더와 Hexnest.exe를 같은 USB 메모리에 복사하십시오.
  5. 필수는 아니지만 유용합니다: 폴더 이름을 Drivers 로 하고 다음 옆에 두십시오: Hexnest.exe. 그러면 Hexnest가 그 폴더를 로컬 드라이버 저장소로 자동 등록합니다. 설정은 필요 없습니다.

포맷한 뒤에

  1. USB 메모리를 꽂고 실행하십시오: Hexnest.exe --rescue. Windows Update에는 전혀 접속하지 않고 로컬 원본만 사용합니다.
  2. 다음으로 가십시오: 백업 및 복원 → 복원, 또는 폴더에서 복원을 골라 백업을 지정하십시오. 모든 패키지가 드라이버 저장소에 추가되고 해당 장치에 연결됩니다.
  3. 네트워크 어댑터에 동작하는 드라이버가 생기면 다음을 누르십시오: 검사와 함께 다시 불러오기 때문입니다.
  4. 대시보드 → 포맷 후 복구 . 아직 빠진 것들이 이번에는 Windows Update에서 대기열에 들어갑니다.
  5. 재시작을 요구하면 받아들이십시오. Hexnest는 로그인할 때 돌아와 대기열의 나머지를 끝냅니다.

백업도, 인터넷도, 준비해 둔 것도 없다면? 다음을 쓰십시오: 대시보드 → 하드웨어 보고서 . 모든 하드웨어 ID를 텍스트 파일로 저장해 동작하는 컴퓨터로 가져간 뒤, 제조사에서 맞는 패키지를 내려받아 풀고, 그 폴더를 다시 가져와 다음으로 설치하십시오: 폴더에서 복원. 네트워크 어댑터부터 시작하십시오. 그것만 되면 나머지는 Windows Update가 알아서 합니다.

명령줄

Hexnest.exe                 # 일반 실행
Hexnest.exe --rescue        # 오프라인 복구 모드 (--offline과 동일)
Hexnest.exe --resume        # 중단된 대기열을 바로 이어서 진행

같은 숫자가 아닌 두 숫자

모니터 페이지는 대부분의 도구가 조용히 틀리는 지점을 조심스럽게 다룹니다. 컴퓨터 전체가 주고받은 양과 프로그램 하나가 주고받은 양은 재는 방식이 서로 다르고, 두 합계는 정확히 같아지지 않습니다 — 그래서 Hexnest는 둘을 따로 보여 주고, 그 이유도 밝힙니다.

같은 정직함이 온도에도 적용됩니다. Windows에는 범용 온도 API가 없습니다. 있는 것은 운영체제 자신의 팬 제어를 위해 펌웨어가 선언하는 ACPI 열 영역뿐이고, 데스크톱 상당수는 그것조차 하나도 선언하지 않습니다. 코어별·GPU별 진짜 값은 SMBus를 통해 제조사 칩에서 오며 서명된 커널 드라이버가 필요합니다. HWiNFO 같은 도구가 그걸 설치하는 이유입니다. Hexnest는 페이지에 숫자를 그리자고 커널 드라이버를 설치하지 않습니다. 그래서 센서가 없는 컴퓨터에서는 카드가 그렇게 말합니다.

정리 도구가 보통 잘못하는 두 가지

시작프로그램을 사용 안 함으로 바꾸는 것이 삭제여서는 안 됩니다. Windows는 사용 여부 플래그를 자체 키에 보관하며, StartupApproved, Hexnest가 쓰는 것은 그것뿐입니다 — Run 값이나 시작프로그램 폴더의 바로 가기는 있던 자리에 그대로 남습니다. 그래서 항목을 다시 켜면 원래 명령줄이 바이트 단위로 되살아나고, 작업 관리자와 Hexnest는 언제나 서로 일치하며, 나중에 Hexnest를 지워도 시작프로그램이 절반쯤 사라지는 일이 없습니다. 더 쉬운 구현 — 값을 지우고 Hexnest 자체 설정에 기억해 두는 방식 — 은 남의 소프트웨어에 대해 Hexnest를 조용히 없어서는 안 될 존재로 만들어 버립니다.

정리 도구가 당신의 파일을 두고 추측해서는 안 됩니다. 캐시는 전부 아니면 전무로 다뤄도 됩니다. 캐시는 스스로 다시 만들어지니까요. 당신의 파일은 그렇지 않습니다. 오래된 다운로드와 제거된 소프트웨어가 남긴 폴더는 크기와 경과 기간과 함께 하나씩 나열되고, 하나씩 체크되며, 삭제가 아니라 휴지통으로 갑니다. 남은 파일 판정은 정말로 추측입니다 — 설치된 모든 프로그램, 실행 중인 모든 프로그램, Program Files 안의 모든 것과 대조하고, 여섯 달 동안 쓰기가 없었을 것을 요구합니다 — 그리고 그 줄에도 추측이라고 적혀 있습니다. 페이지의 모든 크기는 추정이 아니라 실측이라 합계는 실제로 되돌아올 공간이며, 페이지를 열었을 때 체크된 것은 하나도 없습니다.

그리고 메모리 단추. “RAM 확보” 기능은 프로세스의 작업 집합을 디스크로 밀어냅니다. 사용 중인 물리 메모리는 정말로 줄어듭니다 — 그러나 그 프로그램을 다시 쓰는 순간 Windows가 그 페이지를 곧바로 읽어 들이므로, 무엇도 빨라지지 않고 밀려난 프로그램은 잠시 느려집니다. 메모리를 한꺼번에 많이 쓰는 작업을 시작하기 직전에는 쓸모가 있고, 그 밖에는 없습니다. Hexnest는 단추 옆 페이지에 그렇게 적어 둡니다.

Hexnest의 비교 — 부족한 점까지

드라이버 업데이트 도구는 평판이 나쁘고, 대체로 자초한 일입니다. 마흔 개의 문제를 찾아내는 무료 검사, 해결 앞에 놓인 결제 장벽, 상주 서비스, 그리고 친구를 데려오는 설치 프로그램. Hexnest는 정반대로 만들어졌습니다. 그리고 몇 가지 구체적인 면에서는 상용 도구보다 못하기도 합니다. 그런 점들은 묻어 두지 않고 여기에 적어 둡니다.

정직하게 밝히는 단서 조항. Hexnest는 코드 서명이 되어 있지 않습니다. 그래서 처음 실행할 때 SmartScreen과 Smart App Control이 경고합니다. 해법은 파일을 무턱대고 믿는 대신 공개된 SHA-256을 확인하는 것입니다. 관리자 권한이 필요하고, 64비트 Windows 10 1607 이상에서만 동작하며, .NET 런타임 전체가 안에 들어 있어 실행 파일이 크고, Windows가 병렬 설치를 허용하지 않기 때문에 설치는 하나씩 진행됩니다. 드라이버 설치에는 본질적인 위험이 있습니다. 복원 지점 설정은 켜 두고, 백업을 유지하고, 저장소의 고지 사항을 읽으십시오.

자주 묻는 질문

기술적인 질문까지 포함한 전체 목록은 여기에 있습니다: docs/FAQ.md와 함께 다시 불러오기 때문입니다.

Hexnest는 정말 무료인가요?

네. Hexnest는 MIT 라이선스로 공개되어 있고 전체 소스 코드가 GitHub에 있습니다. 유료 등급도, 체험 기간도, 결제 후 풀리는 기능도, 광고도, 끼워 넣은 서드파티 소프트웨어도 없습니다. 검사와 설치는 같은 하나의 제품입니다.

.NET이나 Visual C++ 재배포 패키지를 설치해야 하나요?

아니요. .NET 8 런타임 전체가 Hexnest.exe 안에 자체 포함 단일 파일로 들어 있고, WPF는 vcruntime140_cor3.dll 과 msvcp140_cor3.dll의 전용 복사본을 스스로 가지고 있습니다. 필요한 것은 64비트 Windows 10 버전 1607(빌드 14393) 이상뿐입니다. 실행 파일이 약 65 MB인 이유도 그것입니다.

왜 SmartScreen이나 백신이 Hexnest를 경고하나요?

Hexnest는 코드 서명이 되어 있지 않습니다. 코드 서명 인증서에는 비용이 들기 때문입니다. Windows SmartScreen과 Smart App Control은 평판이 쌓이지 않은 서명되지 않은 실행 파일이라면 무엇이든 경고를 띄웁니다. 게다가 관리자로 실행되고, 드라이버를 설치하고, 예약 작업을 등록하는 단일 파일 앱은 휴리스틱 검사기 눈에는 악성 코드처럼 보입니다.

정직한 대처는 내려받은 파일을 검증하는 것입니다. 다음을 실행하고 Get-FileHash .\Hexnest.exe -Algorithm SHA256 그 결과를, 릴리스와 함께 공개된 Hexnest.exe 안의 checksums.txt 줄과 비교하십시오. 일치하면 그 파일은 공개된 것과 바이트 단위로 같습니다. 직접 소스에서 빌드할 수도 있습니다.

인터넷 없이 포맷 후에 드라이버를 설치할 수 있나요?

네, 바로 그것을 위해 만들어졌습니다. 포맷하기 전에 백업 및 복원 으로 모든 서드파티 드라이버 패키지를 내보낸 다음, 그 폴더와 Hexnest.exe 을 같은 USB 메모리에 복사하십시오. 포맷한 뒤에는 다음으로 시작하십시오: Hexnest.exe --rescue. Windows Update에는 전혀 접속하지 않고 로컬 원본만 사용합니다.

다음 이름의 폴더: Drivers 를 다음 옆에 두면: Hexnest.exe , 자동으로 로컬 드라이버 저장소로 등록됩니다. 직접 푼 제조사 드라이버 폴더도 똑같이 동작합니다. INF 파일을 재귀적으로 대조하기 때문입니다.

문제를 일으킨 드라이버를 되돌릴 수 있나요?

네, 세 가지 방법이 있습니다.

  1. Hexnest는 교체하려는 패키지를 미리 내보내고 그 경로를 기록 항목에 남기므로, 다음으로 다시 설치할 수 있습니다: 폴더에서 복원와 함께 다시 불러오기 때문입니다.
  2. 세션의 첫 설치 전에 드라이버 형식의 시스템 복원 지점을 만듭니다. Windows 시스템 복원 마법사(rstrui.exe)에서 쓸 수 있습니다.
  3. 장치 관리자에 있는 Windows 자체의 드라이버 롤백 단추도 Hexnest와 무관하게 그대로 동작합니다.

Hexnest는 재부팅 뒤에 정말 이어서 진행하나요?

네. 대기열은 상태가 바뀔 때마다 원자적으로 session.json 에 기록되고, Hexnest는 로그인 때 실행되는 예약 작업을 다음 이름으로 등록합니다: Hexnest\ResumeSession. 작업 스케줄러를 쓸 수 없을 때는 HKLM의 RunOnce 값으로 대체합니다. 다음 로그인 때 그 작업이 Hexnest를 --resume 과 함께 다시 실행하고 남은 작업이 이어집니다. 한 세션이 견디는 재시작은 최대 열 번이며, 대기열이 끝나면 작업도 RunOnce 값도 제거됩니다.

Hexnest에는 왜 관리자 권한이 필요한가요?

드라이버 설치는 권한이 필요한 작업입니다. pnputil로 드라이버 저장소에 패키지를 추가하거나 내보내는 일, Windows Update 설치 프로그램을 구동하는 일, srclient.dll 을 통해 시스템 복원 지점을 만드는 일 모두 승격된 토큰이 필요하고, 이어하기 작업은 HKLM 아래에 등록됩니다. Hexnest는 대기열 중간에 “액세스가 거부되었습니다”로 실패하는 대신, 애플리케이션 매니페스트에서 처음부터 승격을 요청합니다.

시작프로그램을 사용 안 함으로 바꾸면 무언가 지워지나요?

아니요. Windows는 사용 여부 플래그를 별도의 키 — ...\CurrentVersion\Explorer\StartupApproved\Run 과 그 두 형제 — 에 보관하고, Hexnest가 쓰는 것은 그것뿐입니다. Run 값이나 시작프로그램 폴더의 바로 가기는 있던 자리에 그대로 남으므로, 항목을 다시 켜면 원래 명령줄이 바이트 단위로 되살아납니다.

덕분에 작업 관리자와 Hexnest가 서로 일치하고, 나중에 Hexnest를 지워도 시작프로그램이 절반쯤 사라지는 일이 없습니다.

정리 기능은 안전한가요?

안전하도록 만들었고, 믿어 달라고 하는 대신 어떻게 그렇게 했는지를 설계로 보여 줍니다:

  • 기본으로 체크된 항목은 없습니다. 페이지는 합계 0으로 열립니다.
  • 모든 경로는 문자열이 아니라 알려진 폴더 API에서 얻고, 개별 삭제는 실행 직전에 자기 범주의 루트 안에 있는지 다시 확인합니다.
  • 재분석 지점은 절대 따라가지 않습니다 — %LOCALAPPDATA% 는 정션으로 가득하고, 그 안으로 들어가는 것이야말로 “캐시 지우기” 기능이 누군가의 문서를 지워 버리는 경로입니다.
  • 열려 있는 파일은 강제하지 않고 건너뛰며, 건너뛴 개수를 알려 줍니다.
  • 당신의 파일은 절대 한꺼번에 선택되지 않고, 휴지통으로 갑니다.

“메모리 확보”가 실제로 효과가 있나요?

지금 이 순간의 물리 메모리를 확보합니다. 그것이 전부입니다. 각 프로세스의 작업 집합을 페이지 파일로 밀어내도록 Windows에 요청하므로 사용 중 메모리는 정말로 줄어듭니다 — 그러나 그 페이지는 사라진 것이 아니라 디스크에 있고, 프로그램이 그 메모리를 다시 건드리는 순간 Windows가 곧바로 읽어 들입니다. 쓰이지 않는 메모리는 낭비된 메모리가 아닙니다. Windows는 이미 그것을 쓸 수 있게 준비해 두고 있었습니다.

따라서 성능 기능이 아니고, Hexnest도 그렇게 내세우지 않습니다. 큰 메모리를 한꺼번에 요구하는 작업을 시작하기 직전이나, 누수가 있는 프로그램이 실제로 얼마나 붙들고 있는지 볼 때 쓸모가 있습니다. 이 단추를 가진 다른 도구들은 하나같이 그렇지 않다고 주장합니다.

왜 온도 카드에 센서가 없다고 나오나요?

그 컴퓨터에는 Windows가 읽을 수 있는 센서가 실제로 없기 때문입니다. 드라이버 없이 Windows가 공개하는 온도는 펌웨어가 자체 팬 제어를 위해 선언하는 ACPI 열 영역뿐이고, 아주 많은 데스크톱 메인보드는 그것을 하나도 선언하지 않습니다. 코어별과 GPU 온도는 SMBus를 통해 제조사 센서 칩에서 오며 서명된 커널 드라이버가 필요합니다 — HWiNFO와 Open Hardware Monitor가 설치하는 것이 바로 그것입니다. Hexnest는 숫자 하나를 채우자고 커널 드라이버를 설치하지 않으므로, 추측하는 대신 센서가 없다고 말합니다.

왜 프로그램별 네트워크 사용량이 컴퓨터 전체 합계와 맞지 않나요?

두 수치는 출처가 다르고, 둘 다 맞습니다. 컴퓨터 전체 합계는 네트워크 어댑터 자체의 바이트 카운터를 더한 값이라 TCP, UDP, QUIC, 브로드캐스트까지 전부 포함합니다. 앱별 수치는 Windows의 TCP 연결 통계(ESTATS)에서 오는데, 이는 커널 드라이버 없이 Windows가 제공하는 유일한 프로세스별 바이트 카운터이며 TCP만 다룹니다. 그래서 영상 통화, 대부분의 게임 트래픽, DNS는 첫 번째 숫자에는 있고 두 번째에는 없습니다. Hexnest는 조용히 적게 보고하는 대신 페이지에서 그렇게 설명합니다.

Hexnest가 백그라운드에서 스스로 업데이트하나요?

하루에 한 번 확인하고 알려 줄 뿐입니다. 다음에서 켜지 않는 한 아무것도 설치하지 않습니다: 설정 → 업데이트. 켜더라도 내려받은 파일은 릴리스의 checksums.txt 와 대조해 검증한 뒤 Hexnest가 닫힐 때에만 교체됩니다 — 드라이버 대기열이 도는 중에는 절대 아닙니다. 오프라인 모드와 복구 모드에서는 확인도 설치도 통째로 건너뜁니다. 확인 자체를 완전히 끌 수도 있으며, 그래도 정보 페이지의 단추는 그대로 동작합니다.

모니터는 백그라운드 서비스인가요?

아니요. 두 모니터 모두 해당 페이지를 열기 전에는 아무것도 측정하지 않고, 페이지를 떠나는 순간 멈춥니다. Hexnest는 여전히 서비스도, 드라이버도, 시작프로그램 항목도 설치하지 않습니다 — 등록하는 것은 중단된 드라이버 대기열을 이어 주는 로그인 작업 하나뿐이고, 그것도 대기열이 끝나면 스스로 사라집니다.

Hexnest는 데이터를 수집하나요?

아니요. 원격 수집도, 사용 통계도, 기기 식별자도 없습니다. 컴퓨터 밖으로 나가는 것은 정확히 두 가지입니다. 하나는 Windows Update 질의로, Windows 자체의 Windows Update 에이전트를 통해 Microsoft로 곧장 가며 오프라인 모드나 복구 모드에서는 통째로 건너뜁니다. 다른 하나는 GitHub 릴리스 API 요청으로, 업데이트 확인을 누를 때 한 번, 자동 확인을 켜 두었다면 하루 한 번입니다. 둘 다 당신의 컴퓨터에 대한 정보를 보내지 않습니다. 평범한 익명 HTTPS GET입니다. 모니터 페이지는 어디로도 아무것도 보내지 않습니다. 거기 나오는 모든 숫자는 로컬에서 읽히며 컴퓨터를 떠나지 않습니다. 그 밖의 모든 것은 당신의 컴퓨터에 있는 %ProgramData%\Hexnest 에 남습니다.

Hexnest 받기

실행 파일을 내려받아 원하는 곳에 두고 두 번 누르면 됩니다. 지우려면 파일을 삭제하고, 원한다면 다음 폴더도 지우십시오: %ProgramData%\Hexnest . 대기열이 끝난 뒤에는 레지스트리에 아무것도 남지 않습니다.
